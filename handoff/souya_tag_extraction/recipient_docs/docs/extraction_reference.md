# 抽出元・抽出内容・タグ付け

## 1. 入力形式と処理方法

| 入力 | 処理 | 主な用途 | 実行環境 |
|---|---|---|---|
| ICAD `.icd` | C# + SXNET | 2D注記、3D部品、材質、質量などの詳細抽出 | Windows + ICAD |
| STEP `.step`／`.stp` | Python | 3D製品名、アセンブリ階層、形状情報の補完 | Python 3.11以上 |
| DXF `.dxf` | Python | 2D文字列、レイヤー、ブロック、寸法情報の補完 | Python 3.11以上 |
| C# raw JSON | Python | ICAD抽出結果の正規化とタグ付け | Python 3.11以上 |

入力ファイルのフルパス、フォルダー、ファイル名、拡張子は、抽出結果の出所を追跡するための属性として保持します。

## 2. ICAD 3Dから取得する情報

C#抽出処理はSXNETを使い、主に次の情報を取得します。

- モデル名、コメント、モデルパス、読み取り専用状態
- ビューシート数、ワークプレーン数
- トップパーツ名、コメント、付加情報
- 部品ツリーの階層パス
- 内部パーツと外部参照パーツの区分
- 部品名、コメント、付加情報、参照モデル名
- 部品ごとの材質ID、材質名、比重
- 質量、重量、体積、表面積、密度
- 重心、モーメント、慣性モーメント候補
- 3Dプレビュー生成結果

部品ごとの材質は、各部品ノードで取得した値を保持します。親部品と子部品の値を自動的に合算しません。

装置カテゴリを判定するときは、装置名・ユニット名・製品名・図面名・部品名と、ICAD 3Dの最上位パーツに設定された`User_WBHNA`を先に確認します。子部品名は後から確認し、上位名称が「シュート」で子部品が「アーム」の場合に、図面全体を「アーム」と誤分類しないようにします。また、「組立図」は図面種別なので、文字列中の「組立」だけでは「組立装置」に分類しません。

## 3. ICAD 2Dから取得する情報

C#抽出処理はSXNETを使い、主に次の情報を取得します。

- ビューシート名、尺度、角度、種別
- 印刷枠番号、用紙サイズ、図面尺度、印刷範囲
- レイヤー番号、レイヤー名、表示・検索状態
- 文字列とその位置、ビュー名、レイヤー番号
- 寸法値、寸法記号、公差
- 幾何要素の種別と位置
- 溶接注記
- 塗装仕様として判別できるKS番号、マシン塗装の明示文字列
- バルーン
- 幾何公差
- 2Dから参照されている3Dパーツ
- 2Dプレビュー生成結果

図枠項目は、同一文字要素内でラベルと値を判定できる場合に抽出します。別々の文字要素を座標だけで自動的に組み合わせる処理は行いません。

英語図枠が`PAINT OR`と`PORTION`のように分割されている場合、`OR`や`PORTION`を塗装値として採用しません。文字列自体で塗装仕様と判断できる`KS42`、`マシン塗装色`、`MC塗装色`などを`paint_instruction_tokens`へ保持します。候補が1種類だけなら`paint`にも同じ値を設定し、複数種類ある場合は代表値を推測しません。

## 4. STEPから取得する情報

Python処理は、STEPに保存されている範囲で主に次の情報を取得します。

- 製品名
- 構成要素名
- アセンブリの親子関係
- 配置情報
- 材質を示す文字列候補
- 形状に関する集計値

STEPのアセンブリ階層は、STEPファイル内の親子関係です。ICADで設定された内部パーツ／外部参照パーツの区分を復元するものではありません。

変換時に一般名へ置き換わった製品名や部品名は、案件名・装置名・正式部品名の確定根拠には使用しません。

## 5. DXFから取得する情報

Python処理は、DXFに保存されている範囲で主に次の情報を取得します。

- レイヤー名
- 文字列
- ブロック参照
- ブロック属性
- 寸法に関する文字列
- 図面番号、名称、材質などの候補
- 製作指示、表面処理、熱処理、硬度などの候補

DXF内に意味情報が残っていない項目は取得できません。文字列やブロック名から判定した値は、根拠と信頼度を付けて候補として保持します。

## 6. 共通属性への正規化

入力形式ごとの差を吸収し、`canonical_attributes`へ共通のキーで格納します。主な分類は次のとおりです。

- 図面情報: 図面番号、図面名、改訂、尺度、用紙サイズ
- 承認情報: 設計者、検図者、承認者、各日付
- 業務分類: 客先、案件、装置カテゴリ、ユニット
- 3D情報: モデル、部品階層、材質、質量、重心
- 2D情報: 図枠、文字列、寸法、公差、溶接、塗装、表面粗さ
- 出所情報: 入力形式、ファイル名、フルパス、フォルダー
- 判定情報: 抽出状態、警告、信頼度、正規化バージョン

全キーの型と必須条件は`schemas\icad-canonical-attributes.v1.schema.json`を参照してください。

## 7. タグ付け

`derived_tags`の各要素には次の情報が含まれます。

| 項目 | 内容 |
|---|---|
| `tag` | 検索・分類に使用するタグ |
| `source` | タグを生成した属性または辞書 |
| `evidence` | 判定に使用した値 |
| `confidence` | 判定の信頼度 |
| `reason` | タグを採用した理由 |
| `manual_flag` | 手動入力かどうか |
| `tag_rule_version` | タグ規則のバージョン |

タグは、図面属性、ファイルパス、文字列、材質、製作指示、初期辞書または運用辞書を照合して生成します。

装置カテゴリが確定した場合は`装置:{値}`、`paint_instruction_tokens`に値がある場合は`塗装:{値}`を生成します。各タグの`source`、`evidence`、`reason`を確認すると、どの属性と文字列を根拠に採用したか追跡できます。

## 8. 取得できない値の扱い

- 取得できない値は、推測値や固定値で補完しません。
- 不明とゼロを区別します。存在を確認できない数値を`0`として扱いません。
- 未対応形式、不正な辞書、不正な入力JSONでは処理を中断します。
- 取得に失敗した項目や低信頼の候補は、`warnings`または候補属性に残します。
- 塗装仕様が複数見つかった場合は候補を`paint_instruction_tokens`へ残し、単一の`paint`を推測しません。
- DXF／STEPは交換形式のため、ICADの材質、質量、付加情報、内部／外部区分を常に保持するとは限りません。
